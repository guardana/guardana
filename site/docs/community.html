Take part in Guardana

Try Guardana, contribute a fix, share an application result, or suggest coverage.

Try the offline starter, bring your own application to a pilot, or contribute a focused fix. The roadmap keeps the release-candidate work separate from additions after stable 1.0.

Try a release candidate

An ordinary install selects stable releases. To opt into a candidate and refresh an existing tool environment:

uvx --upgrade --prerelease allow --from guardana-cli guardana init --starter first-run

Follow the generated project's instructions to find a failure, fix it and edit one check. uvx does not install guardana on your shell's PATH: prefix each README command with the same launcher, as the first-run guide explains. See installing for pip, source and container options. For reproducible team runs, pin the exact reviewed version in your environment.

Join a first run or pilot

  • Join a consented first-run session. Record where the instructions stop being clear; a failed session is useful evidence too.
  • Start an application pilot in GitHub Discussions or email contact@guardana.dev. Begin with synthetic fixtures and harmless tools, then follow the real-application recipe.
  • Try an independently installed extension using the conformance kit. Share its supported surface and a redacted reproduction, including failed and incomplete outcomes.

Each participant chooses what to share. The study guides describe consent and retained evidence. Do not send production secrets, personal records or private prompts to a public issue.

Contribute a focused change

Documentation fixes, tests, examples and maintainer scripts are open during the candidate period. Use CONTRIBUTING.md and the good first issues. Candidates keep the supported surface frozen; new rules and feature additions follow stable 1.0 and demonstrated application needs.

For a bug, include the installed version, the smallest synthetic reproduction, the expected outcome and the observed outcome. Report suspected vulnerabilities privately through SECURITY.md.

Share a result or publication

Send the canonical link, author, publication date when available, and the Guardana version discussed to contact@guardana.dev or Discussions. A useful application report states what was checked, what the evidence could not establish, and which release decision it supported.

The landing page links to selected articles and community posts. A directory listing is distinct from a hands-on review; a fork or star is distinct from a deployment. A quotation or named application story needs the author's consent and a reproducible, redacted result. Suggested links are reviewed for identity, accuracy and source context before publication.

Follow changes

Watch GitHub releases, subscribe to the release feed, or read the project notes. Product status states shipped capabilities and limitations; the roadmap gives conditional priorities, rather than promised release dates.
