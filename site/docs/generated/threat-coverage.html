Threat coverage

Guardana's built-in rules by threat class, with each rule's ID, title, default severity, and command.

This page lists Guardana's 59 built-in rules in 17 threat classes, with each rule's ID, title, default severity, and command. The scripts/generate_docs.py script builds the page from the installed rules and a class file and stops if any built-in rule has zero or multiple classes. Each rule checks for part of a threat, with detection limits explaining what findings prove and taxonomy coverage showing framework mappings.

Unsafe model and dataset loading

Guardana checks for dangerous pickle opcodes, Keras Lambda layers, SavedModel filesystem operators, risky model file and ONNX constructs, chat templates enabling code execution, and remote or custom code on load.

Rule Reports Default severity Runs with
guardana.supply_chain.pickle_opcode Dangerous pickle opcode (arbitrary code on load) CRITICAL scan PATH
guardana.supply_chain.keras_lambda Keras Lambda layer (arbitrary code on model load) HIGH scan PATH
guardana.supply_chain.saved_model_ops TensorFlow SavedModel filesystem operator MEDIUM scan PATH
guardana.supply_chain.model_format Risky construct in a non-pickle model file format HIGH scan PATH
guardana.supply_chain.onnx_graph Risky construct in an ONNX model graph HIGH scan PATH
guardana.supply_chain.chat_template Chat template carries a code-execution gadget CRITICAL scan PATH
guardana.supply_chain.remote_code Remote code execution enabled on model/dataset load HIGH scan PATH
guardana.supply_chain.remote_code_config Model config requests custom-code execution on load HIGH scan PATH

Prevent regressions

Use these checks to catch regressions in scans, live probes, and recorded runs.

  • guardana scan exits 1 when a finding meets fail_on (HIGH by default) and 2 when required coverage is missing, blocking the merge in CI. Use the GitHub Action, a pre-commit hook, or GitLab, Jenkins, and Azure templates. See integrations.
  • guardana baseline records accepted findings as waivers with a reason, approver, and expiry. With scan --baseline, new findings still fail the gate, and findings with expired waivers fail again if still present. See baselines.
  • guardana diff accepted.json current.json exits 1 if a finding appears, is proven, or escalates at or above the fail_on bar, or, at any severity, a check can no longer reach a verdict, a rule stops running, or a file leaves the scan. It exits 2 if the runs cannot be compared. See run comparisons.
  • guardana monitor (beta) reruns endpoint rules with a fresh canary each cycle and alerts if the gate fails, more checks fail to run, or a cycle is worse than the first. See endpoint monitoring.
  • guardana probe --mcp URL --write-mcp-pin PIN saves the approved tool manifest. A later probe with --mcp-pin PIN reports changed tool declarations as CRITICAL. If the pin cannot be compared, the run ends indeterminate (exit 2). See MCP probes.
  • guardana analyze-trace --contract FILE checks recorded runs against 5 contract types (tenant_boundary, approval_required, allowed_scopes, credential_boundary, forbidden_sink). The run ends indeterminate (exit 2) if the trace lacks evidence a contract needs. See trace contracts.
