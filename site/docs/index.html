Guardana documentation

Choose a task, then follow one focused guide.

Start with the root README. Before production use, read Product status, Safe testing, and the Threat model.

First run

  • install.md — install the CLI or a container
  • usage-scan.md — scan artifacts offline
  • usage-probe.md — probe a live endpoint, agent, or MCP server
  • usage-testing.md — run the same checks from pytest
  • how-it-works.md — understand targets, rules, evaluators, and evidence

Run and policy

  • profiles.md — configure rules, gates, budgets, trust, and redaction
  • usage-plan.md — estimate a run before sending requests
  • usage-target.md — verify endpoint capabilities
  • usage-doctor.md — validate and explain effective configuration
  • safe-testing.md — bound active checks and side effects
  • exit-codes.md — interpret command outcomes

Evidence and regression

  • usage-run.md — inspect and migrate saved runs
  • usage-diff.md — compare runs without hiding coverage changes
  • usage-baseline.md — accept risk with an expiry
  • usage-monitor.md — schedule active re-verification
  • usage-calibrate.md — measure evaluator confidence
  • privacy.md — control redaction and retained evidence

Recorded applications

  • usage-analyze-trace.md — grade a recorded execution
  • usage-trace-inspect.md — inspect available evidence dimensions
  • usage-contracts.md — express application-specific invariants
  • usage-import-observations.md — import external tool claims
  • writing-an-integrator.md — produce honest trace evidence

Rules and extensions

  • usage-rules.md — list discovered rules
  • writing-rules.md — create YAML or Python rules
  • usage-rule-test.md — test positive, negative, and inconclusive fixtures
  • extending.md — provide rules, evaluators, targets, or taxonomies
  • usage-new-pack.md — scaffold an installable pack that already passes
  • usage-pack.md — validate and lock extension packs
  • usage-taxonomy.md — resolve framework editions and crosswalks
  • model-formats.md — use the bounded artifact readers

Collector and deployment

  • usage-collector.md — operate the optional collector
  • deployment.md — deploy it with PostgreSQL and TLS
  • integrations.md — connect Guardana to CI and GitHub
  • ../deploy/docker/README.md — use the official images
  • ../deploy/ci/README.md — use GitLab, Jenkins, or Azure DevOps

Architecture and security

  • architecture.md — understand package and trust boundaries
  • threat-model.md — see what Guardana does and does not defend
  • product-status.md — check maturity and known limitations

Reference

These files are generated from the registry and are the source of truth for coverage. Do not edit them by hand.

  • generated/rule-summary.md — counts by surface and severity
  • generated/rule-catalog.md — every built-in rule
  • generated/evaluator-catalog.md — every evaluator
  • generated/taxonomy-coverage.md — framework coverage

Design documents

  • design/README.md — accepted decisions, proposals, and status conventions

Design documents explain why an implementation has its current shape. They are not task guides and may describe rejected or superseded alternatives.
